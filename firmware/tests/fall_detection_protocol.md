# 黄山派跌倒检出率实机测试

## 开测

1. 核对固件版本、手表编号、佩戴侧和松紧。开测前用 USB 执行 `watch_status`，确认 IMU 正常、样本计数在增长、测试表上没有真实联系人或待发送求助。真人动作试次拔掉 USB，使用电池供电。
2. 由已同意参加的健康成年人在有防护垫和人员保护的场地下完成受控试次。先做一组试采，确认观察员能看见屏幕上的「疑似跌倒」。老人的自然跌倒只做经同意的被动观察，按单独的类别记录。
3. 所有试次保持正常运行模式。观察员单独标记触地和屏幕首次显示「疑似跌倒」的时间，时间用同一计时器或视频的秒数。看到提醒后可按 KEY2 取消，等界面回待机再开始下一次。取消不影响该次检出计分。
4. 触地后观察至少 10 秒。当前固件的冲击候选最多保留 6 秒，试点固定用触地后 8 秒作为命中窗口，给观察标记留余量。8 秒后才亮起按迟报记录，计入漏检。试次有效且始终没有提醒时，留空 `first_alert_s`。

## 记录

试采可先做 1 人 4 次并穿插日常动作，核对记录方式。正式试点可做 5 人 × 4 种受控类型 × 2 次，共 40 次。记录前、后、左、右四类，并为每人累计至少 30 分钟日常动作，包括走路、坐下或起身、躺下、弯腰拾物、挥手和穿脱外套。受控跌倒和日常活动的计时段互不重叠。

将 `fall_trials_template.csv` 复制成记录文件。每行表示一次跌倒试次或一段独立的日常观察。

| 列 | 填写方法 |
| --- | --- |
| `participant` 和 `trial` | 用代号和编号，例如 `P01` 和 `01`。同一人的编号保持唯一。 |
| `kind` 和 `scenario` | 类别填 `staged_fall`、`real_fall` 或 `adl`。场景填 `后向`、`快速坐下` 等。 |
| `valid` | 完整有效填 `1`。手表掉电、松脱、标记缺失或试次中断填 `0`，在 `notes` 说明。 |
| `impact_s` 和 `first_alert_s` | 跌倒试次填触地时间、触地后第一条自动提醒时间。日常观察留空。 |
| `wear_s` 和 `alerts` | 日常观察填有效佩戴秒数和自动跌倒提醒次数。跌倒试次留空。 |
| `notes` | 记录异常与试次条件。触地前的自动提醒不能算本次命中，应保留情况供复核。 |

在项目根目录生成汇总：

```powershell
python -B .\firmware\tests\report_fall_trials.py .\.watch-tools\fall_trials.csv --output .\.watch-tools\fall_results.txt
```

报告按受控跌倒和自然跌倒分别计算检出率，并列出方向、参加者、漏检、迟报和命中延迟。日常误报按自动提醒次数除以有效佩戴小时数。零误报时仍记录观察时长。算法阈值若发生变化，另建表，保留独立试次作为最终评估。受控试点的结果仅适用于参与测试的条件。 [现实跌倒与日常误报的测量方法](https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0180318)
